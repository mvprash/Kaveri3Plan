P31|Introduction
P32|The Department of Stamps and Registration (henceforth referred to as “department”) is the custodian of registered public records such as Registration of Marriages and Firms, Documents pertaining to transactions, namely sale, transfer or gift of immovable properties, mortgages, power of attorney, wills and many more. Maintenance and preservation of these critical public records is the prime responsibility of the department. The records or the information associated with registered records are to be made available to the public when requested through defined procedures. The department is also responsible for collecting stamp duty on behalf of the Government for specified transactions. The services are provided through 259 Sub-Registrar Offices (SROs), under the supervision of 34 District Registrar Offices, spread across the state.
P33|The department has computerised the delivery of these services through the development of Kaveri software. KAVERI Online service is a web-based application of the department which provides an interface to the applicants required for documents, marriage and firm registration. It enables applicants to know the details of stamp duty, property guideline value, data entry for document registration and marriage registration, etc. The list of modules of Kaveri 2.0 is available in Annexure 1.
P34|Document scope
P35|This document is a Functional Requirement Specification (FRS) describing the functional features of the PAN Authentication in document registration via Kaveri 2.0. The document is prepared by the Centre for Smart Governance (CSG) and has been approved by the department. The intended audience of the document is the departmental approving authority and the development team.

P45|Functional Requirements
P46|4.1 Application Submission
P47|On the Party Info page of the KAVERI portal, executants can choose any of the identity-proof options like Aadhaar, passport or PAN.
P48|When the user selects PAN as POI and clicks “Verify PAN”, KAVERI’s 2.0 shall allow the user to enter:
P49|PAN number
P50|Name as per PAN
P51|Father's name
P52|DOB and send this payload for the third-party API verification.
P53|The API shall return the result, and KAVERI displays a “Details as per PAN API ” on success.
P54|The fetched details will be stored in the database and can be used at a later stage of the application.
P55|If the Market or the consideration value is less than INR 30 lakhs, the user will be allowed to submit the application for scrutiny.
P56|When the market or consideration value is equal to or more than INR 30 Lakhs:
P57|If all the executants’ PAN Details have already been verified earlier in the party info page, then the user can proceed further.
P58|Else, the user enters PAN details and clicks on the ‘Verify’ button, the system shall validate the PAN details.
P59|If the user does not have PAN, the system should generate Form 60 & 61.
P60|The system presents the user with the option to e-sign or manually sign and upload Form 60/61.
P61|4.2 Scrutiny
P62|SR receives the application for the pre-scrutiny and evaluates MV or CV:
P63|During scrutiny, if SR valuation of MV or CV is ≥ INR 30L for any one property among the selected properties, SR sends back the application to the applicant to verify the PAN.
P64|If MV or CV is less than INR 30L, the application follows the existing flow.
P65|4.3 Presentation and Registration
P66|SR should be able to view PAN details or form 60&61 if available with verification status.
P67|The summary document will have the name as per PAN and verification status.

P72|External integration
P73|This module has an integration with the external system API to verify and validate the applicant's PAN authenticity at the party info screen and fee calculation screen.
P74|Existing integrations like K2, Aadhaar, etc, remain the same.
P75|Assumptions and Dependencies
P76|Assumptions
P77|PAN API will verify the PAN number and display the name as per the PAN.
P78|Name as per the property masters and name retrieved from PAN should be scrutinised by the SR.
P79|Dependencies
P80|This feature has a dependency on the third-party PAN database.
P81|Limitation
P82|The system will not allow the user to make the payment until the PAN details are verified or the Form 60 & 61 are signed using an Aadhar-based e-sign, when the market value or the consideration value is equal to or more than INR 30 Lakhs.
P83|If the PAN API is not working, application submission will not be possible in case if the applicant wants to choose PAN as POI or MV/CV is more than INR 30Lakhs.
