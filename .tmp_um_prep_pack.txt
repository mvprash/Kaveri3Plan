1.3 Observation for the committee
There is no dedicated User Management issue taxonomy in ServiceDesk — recommend creating one in Kaveri 3.0 support operations.
Highest-signal operational failures for UM are: login failures, missing officer names in allocation dropdowns, in-charge not selectable, wrong jurisdiction visibility, and incomplete user relieve/deactivate.
Many “X not reflecting in SR/DEO/FDA login” tickets are workflow bugs, but a subset is caused by incorrect user–role–office assignment — need triage rule during BRD.

2.3 Key business rules stated in FRS (to confirm for 3.0)
Office hierarchy must be created as IGRO → DRO (+ Additional DRO) → SRO (+ Additional SRO).
Data access restricted by Office ID (SRO users) and Jurisdiction ID (district-scoped roles).
Official email ID is the login name; duplicate login rejected.
KGID mandatory for Government Appointed users.
On user create: password generated and Login + Password sent by SMS.
Group privileges override role privileges.
Enable/Disable (Is Active) used to activate or deactivate users/roles/groups.
Privilege matrices deferred to UserMapping_v0.1_Annexure (must be retrieved / rebuilt for 3.0).
2.4 Gaps / risks visible in the FRS proposal itself
TOC sections for IGRO/DRO/SRO/CSG Developer login show “Error! Bookmark not defined.” — incomplete packaging.
SRO Admin powers in §6 list only View users / View privileges, while §1 says SR handles FDA/SDA/DEO mapping — inconsistency to resolve.
No explicit Transfer / Relieving / In-charge / additional charge workflow in the FRS — yet ServiceDesk shows these as real pain points (UM-PP-03, UM-PP-05).
No password reset / unlock / MFA / session policy detail beyond initial SMS password.
No audit trail / maker-checker for privilege changes described in the FRS body.
Citizen user management / eKYC identity is out of this FRS — confirm boundary for 24-Aug discussion.
