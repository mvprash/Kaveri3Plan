About User Management 
 
A user management module KAVERI 2 allows administrators to manage user accounts linked 
to application. It typically provides functionality to create, edit, delete, and search for user 
accounts, as well as manage user roles, permissions, and access control. 
This module helps administrators to efficiently manage large numbers of users, organize 
them into groups, and assign appropriate permissions to each group and user. 
Some common features of a user management module include user authentication, 
password management, user registration and activation, office creation and management, 
Roles, post creation and management. Overall, the user management module is a critical 
component of Kaveri 2 applications and helps ensure the security and integrity of user data 
and resources.

1.User Management Admins 
 
The user management module will be handled by following Roles 
1. Super Admin (KPMU) 
The super admin is responsible for creating users, roles, groups and granting privileges 
and access of different functionalities of the Kaveri 2.0 application. KPMU will have the 
responsibility of user administration of all department users of the entire state. 
 
2. Department Admin 
IGR of the Department of Stamps & Registration will be Department admin. The 
department admin will be a super admin for administrative approvals. Department 
admin will perform the same action as KPMU and will assign DIGR/AIGR roles to 
respective users.   
 
3. DIGR Admin 
 
DIGR Admin will assign the roles to DR/HQA/SR/FDA/SDA/DEO users. 
 
4. District Admin 
District Admin will be District Registrar will be head of respective district, will handle 
the mapping of roles and access to HQA/SR/FDA/SDA/DEO users of their respective 
jurisdiction. 
 
5. Sub-registrar office Admin 
Sub registrar office Admin will be Sub Registrar, will head of the  sub-registrar office 
and he/she would be approving authority to personnel reporting directly to him/her. 
SR admin will handle the mapping of roles and access to FDA/SDA/DEO users of his 
office.

2.Basic User Management Functions  
 
1. Creates Office Type -  Various office types likes IGRO/DRO/SRO/Additional 
DRO/Additional SRO will be created using this functionality 
2. Create Office – Offices like SRO Gandhinagar, DRO Mysore etc., will be created using 
this functionality 
 
3. Add Post – Using this functionality number of post and type of post in each office 
can be described. 
 
4. Add  Role -  Roles like IGR/DIGR Law & Administration/DIGR Audit/DIGR 
Intelligence/DIGR Vigilance/DIGR CVC/DIGR Enforcement/AIGR Computers/AIGR 
Administration/AIGR Audit/Law Officer/Accounts Superintendent/Superintendent 
Audit/Statistical Inspector/SR Administration/SR Computers/FDA/SDA/DR/SR will be 
created using this functionality. 
 
5. View/Edit Role -  This functionality will display list of Role and further provisions an 
edit option to change role name or enable/disable role. The privilege of view and edit 
can be set in Modules/Sub module/Functions mapping 
 
6. Mapping of Roles to Modules / Sub Modules / Functions – This option shall be used 
to define access to role with respect to Module, Sub module and Functions. This will 
be important functionality which will govern all kind of privileges to user/role. 
 
7. Add user – This functionality will be used create new departmental user to whom 
application access to be provided . 
 
8. View/Edit user – This functionality lists all the user or specific to DRO/SRO. Further 
based on the privilege Edit User functionality would be provided  
 
9. Create Group - A Group can be created using this functionality and roles can be 
assigned to this group. Group can be  like IGR office, DR Office, SR Office. Group 
privilege will over ride role privilege. 
 
10. View/Edit Group – This functionality lists the groups created. Further if the user has 
privilege edit option wherein group name can be changed, or enable/disable group 
option will be provided.  
 
11. Map Group to Modules/Sub Modules/ Functions - This option shall be used to define 
access to group with respect to Module, Sub module and Functions. This will be 
important functionality which will govern all kind of privileges to user/role. Privilege 
set here shall over ride role privilege.

3.2. Create Office 
 
 
 
Functional Step by Step Process 
 
Here we create each office of Department of Stamps & registration to use the Kaveri 2.0 
online services. All offices must be created initially in following hierarchy. 
IGRO followed by all DRO then SRO under each DRO.  
Once existing Offices are created any new office can be added as per its jurisdiction 
1. Admin login to Kaveri application 
2. Admin selects “User Management->Office->Add office” option. 
3. Scans & uploads Government Order to Create new office. This would be 
mandatory going forward if any new office is created other than existing 298 
offices.

4. Office Type: Select the office type from the list IGRO/DRO/SRO/Additional 
DRO/Additional SRO. This is mandatory field and list would be auto populated 
based on Office type created in previous functionality. Based on the office type 
selected it would ask for jurisdiction it belongs to. Further if any DRO or SRO is 
created DDO code (used for Khajane II payment) needs to be added. This will be

Case 3: 
In case DRO needs to be created then IGRO will be the jurisdiction and DDO code

9. Office address: We can input the office address where the office is located.

10. Phone:  Enter landline Number as point of contact. This will be mandatory field 
11. District: Select the District from the drop down. This is mandatory. 
12. Pin code:  Enter the pin code. This will be mandatory field. 
13. Is active: To Enable or disable office. This is only for office type SRO and it is 
mandatory

3.7. Add User  
 
 
Functional Step by Step Process 
1. Here we create each user working under IGR office of Department of Stamps & 
registration to use the Kaveri 2.0 application.  
2. Admin selects “User Management -> User -> Add User” option. 
3. User Type: Select the user type from the list Government Appointed/Contract. 
4. Role ID: Selected from drop down. It can be FDA/SDA/DEO. This is mandatory. 
5. KGID: KGID number shall be entered, it is mandatory for all government appointed 
users. This is mandatory for Govt Appointee.

6. Official Email ID: Official email id shall be entered as login name. System checks 
whether login name (Official email id) exists, if yes, displays message as user exists

7. Office Name: Assign office to the user, jurisdiction id is automatically assigned. 
Based on the office id data access has be restricted to only for that office for all SRO. 
Based on the Jurisdiction ID data access has to be restricted to only for their 
Jurisdiction.  
8. First Name, Middle Name & Last Name:  Need to enter name of the User. First

10. Date of Joining: Enter date of joining only for govt appointee

18. Click on “Save & Submit”.
